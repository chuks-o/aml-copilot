# 0018 — Generated clients, committed and checked for staleness

**Status:** Accepted · **Ticket:** T07 · **Date:** 2026-10-16

## Context

Two contracts drive three clients:
- `backend/openapi.yaml` ([0014](0014-cases-api-contract.md)) gives the REST client for the web BFF and the REST client for backend modules.
- `web/src/graphql/schema.graphql` ([0016](0016-console-graphql-schema.md)) gives the resolver types for the GraphQL route and the operation types for the console.

Clients written by hand drift from their contracts silently. Generated clients drift too, if someone edits a contract and forgets to regenerate. The generators were first tried on the real contracts before anything was chosen:

| Generator | Result |
| --- | --- |
| openapi-python-client 0.29.1 | Clean. Errors parse into typed `Problem` / `ValidationProblem`; `If-Match` and `Idempotency-Key` are required arguments. `mypy --strict`: 12 `arg-type` errors, all in `client.py`. Ruff with our rules: 132 style errors. |
| openapi-typescript 7.13.0 | Clean on TypeScript 6.0, despite declaring a TypeScript 5 peer. |
| graphql-codegen `typescript-urql` 5.0.1 | **Crashes** (`Cannot read properties of undefined (reading 'some')`). It declares graphql ≤ 16; we use 17. |
| graphql-codegen `typed-document-node` | Clean. |

## Decision

1. **Three outputs, all regenerated by `make codegen` and committed:**

   | Output | From | Generator |
   | --- | --- | --- |
   | `web/src/generated/cases-api.ts` | `backend/openapi.yaml` | openapi-typescript (types only); used through openapi-fetch |
   | `backend/src/aml/clients/cases_api/` | `backend/openapi.yaml` | openapi-python-client (`--meta none`: a package, no `pyproject`) |
   | `web/src/generated/graphql.ts` | `schema.graphql` + `web/src/graphql/operations/*.graphql` | graphql-codegen: `typescript`, `typescript-resolvers`, `typescript-operations`, `typed-document-node` |

   Each generated file says it is generated. Never edit them; change the contract and run `make codegen`.
2. **Staleness guard: `make codegen-check`.** It runs `make codegen`, then fails if `git status --porcelain` shows any change under `web/src/generated` or `backend/src/aml/clients/cases_api`, listing the stale files. It uses `git status` rather than `git diff` because a newly generated file (a new endpoint or model) is untracked, and `git diff` doesn't see untracked files. A new CI job, `codegen`, runs it with both toolchains.
3. **Typed urql hooks = urql's own `useQuery` / `useMutation` / `useSubscription` + generated `TypedDocumentNode`s** (`CaseQueueDocument`, `DecideCaseDocument`, …). The document carries its result and variable types, so `useQuery({ query: CaseFileDocument, variables })` is fully typed. Compile-time assertions in `web/test/graphql-operations.test.ts` pin this down.
4. **The operations' source of truth moves to `web/src/graphql/operations/*.graphql`**, because codegen can't read Markdown. `docs/graphql-queries.md` still shows them, and a test asserts that each block is identical to its file. Codegen rejects operations that are invalid against the schema.
5. **One `graphql.ts`.** `typescript-operations` v6 emits its own copies of the enums and inputs it uses, which collide with the `typescript` plugin's. `importSchemaTypesFrom: "src/generated/graphql.ts"` points it at the types already in the same file. This produces a harmless type-only self-import, `import type * as Types from './graphql'`.
6. **Generator configuration:**
   - `enumsAsTypes`: string unions, no runtime enum objects, compatible with `verbatimModuleSyntax`.
   - `useTypeImports`.
   - `strictScalars`, with `DateTime` and `Decimal` both mapped to `string`. An unmapped scalar fails generation instead of becoming `any`.
   - No resolver `mappers` yet. Resolver parents are typed as the GraphQL types until T28 decides whether they're REST models.
7. **Generated Python is formatted by our locked Ruff** (the generator's only post-hook is `ruff format .`), **excluded from Ruff lint** (`lint.exclude`), and **kept under `mypy --strict`**, with one override: `disable_error_code = ["arg-type"]` for `aml.clients.cases_api.client`, where `__exit__`/`__aexit__` forward `*args: Any`. There's no `ruff check --fix` hook, so the output doesn't depend on our lint rules.
8. **"Every module outside `aml.api` calls the API only through `aml.clients`" is enforced.** A new import-linter contract, `http-only-via-clients` (with `include_external_packages = true`), forbids importing `httpx` from every top-level `aml` module except `aml.clients`. `tests/test_architecture.py` keeps its module list complete. Together with `workers-use-http` (no importing `aml.api`), the generated client is the only route to the API.
9. **One factory per side**, so base URL, timeout, and later auth and retries are set in one place:
   - Python: `aml.clients.cases_api_client()`, with `AML_CASES_API_URL` (default `http://127.0.0.1:8000`) and `AML_CASES_API_TIMEOUT` (10 s), and `raise_on_unexpected_status=True`.
   - Web: `createCasesApiClient()` in `web/src/lib/cases-api.ts`, server-side, reading the same variable.
   - Compose sets `AML_CASES_API_URL=http://api:8000` for the backend containers and the web container.
10. **Generators are pinned, locked dependencies**, at versions released at least two weeks earlier:
    - web dev dependencies: openapi-typescript 7.13.0, `@graphql-codegen/cli` 7.4.3, `typescript` 6.1.0, `typescript-operations` 6.1.9, `typescript-resolvers` 6.1.0, `typed-document-node` 7.1.1, `add` 7.1.1;
    - web runtime: openapi-fetch 0.17.0;
    - backend dev: openapi-python-client 0.29.1;
    - backend runtime: httpx, attrs, python-dateutil.

## Alternatives

- **Generating at build time and git-ignoring the output.** Reviewers wouldn't see what a contract change does to the clients, IDEs and type-checks would need a codegen step first, and generator upgrades would change code silently. The ticket requires committing, and these are the reasons.
- **`git diff --exit-code` as the check.** It misses new untracked files, the most likely result of adding an endpoint.
- **`typescript-urql` for named hooks** (`useCaseFileQuery`). It crashes on graphql 17, declares graphql ≤16, and is community-maintained; The Guild points users to typed documents instead.
- **A small local codegen plugin for named hook wrappers.** That's our own generator to maintain, for names only.
- **graphql-codegen `client-preset`.** It writes a directory of files and expects `graphql()` calls inside components; the ticket names one file.
- **Keeping the operations only in Markdown** and extracting them at codegen time. Fragile, and an odd source of truth.
- **`npx` / `uvx` for the generators.** Unlocked transitive versions and network access at codegen time are the usual cause of codegen checks that fail at random.
- **Linting generated Python.** 132 style errors in code nobody edits.
- **Excluding generated Python from mypy.** Type safety is the reason to generate in the first place.
- **Custom generator templates** to remove 12 type errors from one file, or to drop the sync functions (openapi-python-client always emits `sync` and `asyncio`). That's template maintenance on every upgrade. Backend code uses the `asyncio` variants by convention.
- **Callers building their own clients.** Base URLs and timeouts drift, and there's no single place to add retries.

## Consequences

- Any change to `openapi.yaml`, `schema.graphql` or an operation file needs `make codegen` and a commit of the output, or CI's `codegen` job fails.
- Generator upgrades show up as reviewable diffs in generated code, not as silent behaviour changes.
- Backend modules can't use `httpx` directly, even for non-API calls. When something other than the Cases API needs HTTP (an LLM provider, say), its client goes in `aml.clients` too, or this contract gets an explicit exception in a record.
- The retry helper (CLAUDE.md, added later) slots into the two factories, not into callers.
- `make codegen-check` needs a clean working tree for the generated paths, which is fine in CI. Locally, commit or stash first.
